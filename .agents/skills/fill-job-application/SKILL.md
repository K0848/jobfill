# 网申填写

以用户指定的资料和当前页面为依据，在授权范围内核对、填写并读回。仓库根目录包含 `tools/` 与 `site-hints/`；从仓库根目录执行命令。用户只要求检查时保持只读。

## 事实和权限

- 确认用户指定的 Markdown 路径和目标页面；没有资料或目标时询问，不猜测个人事实。资料格式见 `examples/profile.example.md`，真实资料与运行产物不要提交或分享。
- 核对已有值与空字段：按字段语义和经历的学校、公司或项目 `identity` 对应资料。现值正确则保留；冲突、来源不明或身份不唯一时保留现值并列为待确认。只有用户授权且来源明确的更正才能覆盖已有值。
- 普通字段值须来自 `profile.*` 对应字段；用户在会话中确认的派生值使用 `user.*`，并提供 `sourceText` 说明依据。缺少依据不填写；不得把不同字段、记录或日期精度混用。
- 不点击保存、下一步、提交、协议或验证码；不默认修改个人资料和投递跟进表。涉及附件或其他外部写入时，先按用户的当次授权处理。

## 操作

1. 使用 Huashu Chrome 查看当前标签和页面，绑定确切的目标标签，集中观察字段、已有值、必填性、控件及所属记录。先确认桥接可用；连接失败时停止该页面操作。
2. 依据当前观察及资料生成 `plannedFields`。每项标注 `label`、`sourceKey`、`value`、可重新定位的 `selector` 或 `find`、控件类型和需要时的 `recordIdentity`。同一 `sourceKey` 不重复用在多个计划字段。页面变化时重新观察受影响区域。
3. 普通字段和已验证的控件可经批量 CLI 执行；将请求 JSON 放在本机受保护的位置，不把资料值或完整请求拼到命令行。请求结构见 `examples/request.example.json`，必须替换为当前页面、资料路径和实时观察结果。

   ```powershell
   node tools/jobfill-batch-cli.js --request-file data/request.json
   ```

   相同 URL 存在多个标签时设置 `snapshotHint.tabId`。CLI 对目标标签、来源、现值和读回进行检查；如需更正已有值，提供经授权的 `authorizedReplacement.expectedCurrentValue` 和 `sourceText`。不要直接调用内部执行器绕过这些检查。
4. 对 CLI 不支持或已知不稳定的控件，使用授权的浏览器操作，并核对实际选中值和页面校验。复杂弹层需找到唯一候选；输入框中的搜索文字不等于完成选择。无匹配、歧义、页面导航或连接失效时停止相关项。工具失败时先核对页面实际状态，再用可行方式处理尚未完成的明确字段，避免重复写入。
5. 合并结果，分别说明已有值核对、已填写且读回匹配、待确认或未验证项。`attempted` 只表示本次读回匹配；`pending`、`unsupported`、`blocked`、`write_unverified` 不表示完成。区分页面填写、网站保存和最终提交，交由用户检查后自行保存或提交。

可按站点参考 `site-hints/` 中的控件说明，但应以当前页面为准。不要将历史示例当成对当前页面的验证。
