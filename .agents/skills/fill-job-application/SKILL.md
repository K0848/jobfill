# 网申填写

以用户指定的资料和当前页面为依据，在授权范围内核对、填写并读回。仓库根目录包含 `tools/` 与 `site-hints/`；从仓库根目录执行命令。用户只要求检查时保持只读。

## 事实和权限

- 确认用户指定的 Markdown 路径和目标页面；没有资料或目标时询问，不猜测个人事实。资料格式见 `examples/profile.example.md`，真实资料与运行产物不要提交或分享。
- 核对已有值与空字段：按字段语义和经历的学校、公司或项目 `identity` 对应资料。现值正确则保留；冲突、来源不明或身份不唯一时保留现值并列为待确认。只有用户授权且来源明确的更正才能覆盖已有值。
- 普通字段值须来自 `profile.*` 对应字段；用户在会话中确认的事实或授权内基于已确认资料生成的派生值使用 `user.*`，并提供 `sourceText` 说明依据。缺少依据不填写；不得把不同字段、记录或日期精度混用。
- 不为本流程固定模型或推理强度，遵从用户的设置。不代替用户点击招聘网站的保存、下一步、提交、协议或验证码；不默认修改个人资料和投递跟进表。涉及附件或其他外部写入时，按用户的明确授权处理。
- 如本机存在 `data/personal-workflow.md`，先读取其中已确认的个人资料路径和跟进授权；该文件与真实资料保持 Git 忽略。不存在时按本文件的通用授权边界执行。
- 经用户授权更新跟进表时，所有聊天统一调用 `python -B tools/update-job-tracker.py --workbook <工作簿> --request-file <请求JSON>`，见 [更新契约](../../../docs/job-tracker.md)。工具按路径互斥、锁后重读并核对写入；禁止用旧快照或另写无锁脚本覆盖。仅维护公司、岗位、完整真实超链接和状态，新增行继承序号及格式，其他列不主动补写或清空。
- 使用该工具前明确状态口径：`completed: true` 在空状态写“筛选中”，表示填写完成、等待用户核对后提交，不表示已提交；`false` 的新记录状态留空。用户尚未同意此口径时先确认；已有笔试、面试等非空状态保留。占用、超时、身份冲突或结构不支持时保留页面成果，核对实际记录后通过同一入口恢复，不绕过锁或重建替代表。
- 自我评价按岗位提炼能力，不复述实习或项目。读取完整 JD，选取最相关的 2—3 项已确认能力，简短概括“能做什么、如何开展工作”；经历仅用于内部核实，不重复公司、项目、过程和指标。避免技术名词堆砌、空泛形容词和未经确认的职业意愿。已有岗位定制版本先核对，不用通用版本覆盖；缺 JD 只暂停该项。使用 `user.*` 和 `sourceText` 记录 JD、个人资料及改写依据。
- 技能、特长、职责可按字段摘取、压缩已有资料，不新增事实、提高能力等级或改变职责范围；去掉内部备注、资料标题和无关网址。改写须记录来源及删改依据。
- 偏好按当前指令、本次申请确认、明确通用偏好的顺序使用；已确认事项不重复问，本次城市选择不自动升级为长期偏好。长期资料写回仍须明确授权。

## 操作

1. 使用 Huashu Chrome 查看当前标签和页面，绑定确切的目标标签，集中观察字段、已有值、必填性、控件及所属记录。先确认桥接可用；连接失败时停止该页面操作。
2. 依据当前观察及资料生成 `plannedFields`。每项标注 `label`、`sourceKey`、`value`、可重新定位的 `selector` 或 `find`、控件类型和需要时的 `recordIdentity`。同一 `sourceKey` 不重复用在多个计划字段。页面变化时重新观察受影响区域。
3. 普通字段和当前页面已验证的控件优先经批量 CLI 执行；用户明确要求直接操作时遵从。不要由 Agent 逐字段重复调用浏览器工具，CLI 内部仍需进行必要的现值和读回检查。将请求 JSON 放在本机受保护的位置，不把资料值或完整请求拼到命令行。请求结构见 `examples/request.example.json`，必须替换为当前页面、资料路径和实时观察结果。

   ```powershell
   node tools/jobfill-batch-cli.js --request-file data/request.json
   ```

   相同 URL 存在多个标签时设置 `snapshotHint.tabId`。CLI 对目标标签、来源、现值和读回进行检查；如需更正已有值，提供经授权的 `authorizedReplacement.expectedCurrentValue` 和 `sourceText`。不要直接调用内部执行器绕过这些检查。
4. 对 CLI 不支持或已知不稳定的控件，使用授权的浏览器操作，并核对实际选中值和页面校验。复杂弹层需找到唯一候选；输入框中的搜索文字不等于完成选择。无匹配、歧义、页面导航或连接失效时停止相关项。工具失败时先核对页面实际状态，再用可行方式处理尚未完成的明确字段，避免重复写入。每个 Agent 只操作自己任务绑定的目标页面并显式传 tabId，不同网申聊天可并行；本页 CLI 与直接操作顺序执行。
5. 合并结果，分别说明已有值核对、已填写且读回匹配、待确认或未验证项，以及使用的执行路径和实际恢复情况。`attempted` 只表示本次读回匹配；`pending`、`unsupported`、`blocked`、`write_unverified` 不表示完成。区分页面填写、网站保存和最终提交，交由用户检查后自行保存或提交。仅创建任务需要的临时文件，确认无后续用途后清理本次生成的临时文件。

可按站点参考 `site-hints/` 中的控件说明，但应以当前页面为准。不要将历史示例当成对当前页面的验证。

## 地区选择

现居地、籍贯、户口、学校、实习城市按对应事实填写，工作和面试城市分别按对应偏好选择。站点只到省或市时按其粒度映射。先读取完整候选再按已确认规则排序，不能把“都在广东”当作具体先后依据；仅确认岗位唯一所在地时直接匹配，涉及迁居等意愿时按用户确认处理。

打开字段、逐级选择、完成控件内部“确定”，关闭弹层后读回真实选中值，检查后一级联动字段未被清空。搜索文字和候选高亮不等于选中；控件内部确定属于字段填写，不等于网页保存或提交。
